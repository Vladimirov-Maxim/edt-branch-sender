# edt-branch-sender

Плагин 1C:EDT, который переносит изменения ветки в базу, где EDT нет.

По одной кнопке он берёт объекты метаданных, изменённые в текущей ветке git относительно базовой
(например, `origin/develop`), выгружает их в XML формата конфигуратора и отправляет zip-пакетом в отдельную
ветку git. Оттуда пакет можно забрать на любой машине и загрузить в базу частичной загрузкой конфигурации
(`/LoadConfigFromFiles … -partial`) — без EDT, без полной выгрузки и без ручного переноса файлов.

В штатном мастере EDT «Экспорт в XML» есть только полная выгрузка. Плагин использует тот же механизм
экспорта, но только для изменённых объектов, поэтому пакет задачи занимает секунды и сотни килобайт.

## Возможности

- Список объектов — по git: коммиты ветки с момента ответвления от базовой и, по желанию, незакоммиченные
  правки.
- Объект выгружается целиком: описание, модули, формы, макеты. Из корня конфигурации — только
  `Configuration.xml` (модули конфигурации — по флажку).
- Пакет `<имя ветки>.zip` (`xml\` + `info.txt`) коммитится в отдельную ветку пакетов и отправляется на
  сервер. Повторная отправка перезаписывает пакет; прежние версии остаются в истории.
- Отправка возможна, только если ветка содержит актуальную базовую ветку — иначе пакет откатил бы чужие
  правки тех же объектов. В пакет записывается коммит базовой ветки, на который он рассчитан.
- Удалённые в ветке объекты перечисляются в `info.txt` (частичная загрузка их не удаляет).
- Рабочая копия проекта не переключается и не меняется: ветку пакетов плагин держит в собственном клоне.

## Требования

- 1C:EDT 2025.2 (на других версиях не проверялся).
- Проект открыт в EDT из рабочей копии git.
- Git for Windows; `git push` в репозиторий проекта проходит без запроса пароля в консоли (обычно
  учётные данные хранит Git Credential Manager).

## Установка

1. Закрыть EDT.
2. Скопировать `plugin\edtbranchsender_<версия>.jar` в каталог `dropins` установки EDT (создать, если его
   нет). Для EDT, установленной через 1C:EDT Start:
   ```
   %LOCALAPPDATA%\1C\1cedtstart\installations\<версия EDT>\1cedt\dropins
   ```
3. Запустить EDT. В «Окно → Параметры» появится раздел **«Пакет изменений»**.

Обновление — заменить jar в `dropins` при закрытом EDT. Удаление — удалить jar.

## Ветка пакетов

Пакеты хранятся в отдельной ветке репозитория проекта — пустой, без исходников и без общей истории с ними.
Плагин её не создаёт. Создать один раз можно так, не трогая рабочую копию:

```
git init C:\temp\packages-init
git -C C:\temp\packages-init commit --allow-empty -m "Ветка пакетов"
git -C C:\temp\packages-init push <URL репозитория проекта> HEAD:refs/heads/packages
```

Каталог `C:\temp\packages-init` после этого можно удалить. Можно использовать и отдельный репозиторий —
тогда в настройках указывается его URL.

## Настройка

«Окно → Параметры → Пакет изменений»:

| Поле | Что это |
|---|---|
| Проект EDT | проект конфигурации из рабочей области |
| Сравнивать с | базовая ветка, например `origin/develop`; ветка удалённого репозитория перед отправкой обновляется (`git fetch`) |
| Включать незакоммиченные правки | брать в пакет и незакоммиченные изменения (по умолчанию да) |
| Включать модули конфигурации | выгружать модули корня конфигурации вместе с `Configuration.xml` |
| Репозиторий | имя удалённого репозитория рабочей копии (`origin`) или URL отдельного репозитория |
| Ветка пакетов | существующая ветка без исходников проекта, например `packages` |

## Использование

1. Переключиться на ветку с изменениями и подтянуть в неё актуальную базовую ветку (merge или rebase).
2. Открыть «Окно → Параметры → Пакет изменений», нажать **«Обновить»**: строка «Синхронизация» должна
   показать, что ветка содержит базовую. Если ветка отстаёт, кнопка «Отправить» неактивна.
3. Нажать **«Отправить»**. Ход виден в журнале под кнопкой; страницу можно закрыть — итог придёт
   сообщением.

Результат — файл `<имя ветки>.zip` в ветке пакетов, например `feature/TASK-123.zip`.

## Формат пакета

| Путь | Что это |
|---|---|
| `xml\` | XML изменённых объектов в формате выгрузки конфигуратора |
| `info.txt` | UTF-8 с BOM: ветка и коммит, базовая ветка, коммит базы, версия формата выгрузки, список объектов, удалённые объекты, сообщения EDT |

Коммит пакета в ветке пакетов: `<ИД задачи>: пакет <ГГГГММДД_ЧЧММ>`, далее ветка, коммит исходников и
`Коммит базы: <хеш>`.

Пример загрузки распакованного пакета пакетным конфигуратором (`<список>` — все файлы под `xml\` с
абсолютными путями, по одному в строке, UTF-8):

```
1cv8.exe DESIGNER /F <каталог базы> /N <пользователь> /P <пароль>
  /LoadConfigFromFiles <распакованный>\xml -listFile <список> -partial
  /UpdateDBCfg /Out <лог> /DisableStartupDialogs
```

Пакет рассчитан на базу, соответствующую коммиту базы из `info.txt`. Данные (константы, элементы
справочников) пакет не переносит — только конфигурацию.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| «отстаёт от … на N коммит(ов)» | подтянуть базовую ветку в текущую, нажать «Обновить» |
| «Ветка сравнения не найдена» | проверить поле «Сравнивать с» |
| «В рабочей копии есть незакоммиченные правки…» | закоммитить правки или включить флажок «Включать незакоммиченные правки» |
| «Рабочая копия не на ветке (detached HEAD)» | переключиться на ветку |
| «Изменённых объектов нет» | ветка не отличается от базовой |
| «Не удалось получить ветку …» | проверить «Репозиторий» и «Ветка пакетов»; ветка должна существовать |
| «В ветке … лежат исходники проекта» | в «Ветка пакетов» указана рабочая ветка — указать ветку пакетов |
| ошибка push или авторизации | проверить, что обычный `git push` из рабочей копии проходит |
| раздела «Пакет изменений» нет | плагин не загрузился: причина — в журнале ошибок EDT или в `.metadata\.log` рабочей области |

Путь к `git.exe`, если он не в `C:\Program Files\Git\cmd` и не в `PATH`, задаётся строкой
`-Dedtbranchsender.git=<путь>` в `1cedt.ini`.

## Сборка

```
powershell -File build.ps1 [-Install]
```

Компиляция `javac` из JDK 17 комплекта EDT против jar-ов p2-пула 1C:EDT Start
(`%USERPROFILE%\.p2\pool\plugins`), без Maven. Результат — `dist\edtbranchsender_<версия>.jar` и его копия
в `plugin\`; с `-Install` — копирование в `dropins` (EDT должен быть закрыт). При изменениях повышайте
`Bundle-Version` в `bundle\META-INF\MANIFEST.MF`: EDT кеширует бандл по версии.

| Файл | Роль |
|---|---|
| `bundle\plugin.xml`, `bundle\META-INF\MANIFEST.MF` | описание бандла, регистрация страницы параметров |
| `Activator` | точка входа, доступ к сервисам и экспорту EDT, настройки, журнал |
| `SenderPreferencePage` | страница «Пакет изменений» |
| `PackageSender` | сценарий отправки и проверки |
| `XmlExporter` | git → объекты → XML через экспорт EDT |
| `Git` | запуск git с тайм-аутом, без консольного запроса пароля |
