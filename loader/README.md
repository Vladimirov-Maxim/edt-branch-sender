# Загрузка пакета в базу

`load-package.cmd` загружает пакет изменений, отправленный плагином, в базу 1С. Работает без EDT и без окон —
через конфигуратор в пакетном режиме, поэтому его можно запускать вручную из консоли или встроить в
автоматизацию (планировщик, CI, центр администрирования).

## Что внутри

| Файл | Что это |
|---|---|
| `load-package.cmd` | точка входа: запускает `load-package.ps1` с нужными параметрами PowerShell |
| `load-package.ps1` | сам скрипт |

Оба файла должны лежать в одном каталоге. Скачать их одним архивом — `load-package.zip` из
[последнего релиза](https://github.com/Vladimirov-Maxim/edt-branch-sender/releases/latest).

## Что нужно на машине

- Windows с Windows PowerShell 5.1 (есть в Windows 10 / Server 2016 и новее).
- Платформа 1С (`1cv8.exe`) — та же версия, что у сервера 1С.
- Git for Windows — только если пакет берётся прямо из ветки пакетов. Доступ к репозиторию — без запроса
  пароля в консоли (Git Credential Manager, токен в URL или SSH-ключ).
- Пользователь 1С с правом «Администрирование» в целевой базе.

## Что он делает по шагам

1. **Получает пакет.**
   - С `-Package` — берёт указанный zip.
   - С `-Repo` и `-Branch` — делает лёгкий клон ветки пакетов (только последний коммит, без содержимого
     файлов) во временный каталог и достаёт из неё один файл `<ветка задачи>.zip`. Выводит коммит, которым
     пакет был отправлен.
2. **Распаковывает** пакет во временный каталог и выводит `info.txt`: ветку и коммит, коммит базы, список
   объектов и удалённые объекты.
3. **Собирает список файлов** — все файлы под `xml\` с абсолютными путями.
4. С `-BackupCf` — **сохраняет текущую конфигурацию** базы в `.cf` (`/DumpCfg`). Если сохранить не удалось,
   загрузка не выполняется.
5. **Загружает** файлы частичной загрузкой:
   `DESIGNER /LoadConfigFromFiles <xml> -listFile <список> -partial /UpdateDBCfg`.
   Без `-NoUpdateDB` сразу обновляет конфигурацию базы данных.
6. Выводит журнал конфигуратора и итог. **Код возврата:** `0` — загружено, `1` — ошибка.
7. Удаляет временный каталог. При ошибке каталог остаётся (пакет, список файлов, журнал) — путь выводится
   в конце.

Скрипт ничего не хранит: ни настроек, ни паролей.

## Как запускать

Открыть `cmd` или PowerShell в каталоге со скриптом. Запуск без параметров выводит справку.

Пакет прямо из ветки пакетов в серверную базу:

```
load-package.cmd -Repo https://git.example.com/group/project.git -Branch feature/TASK-123 -Server srv1c -Ref test_base -User Администратор
```

Из zip-файла в файловую базу, с сохранением конфигурации перед загрузкой:

```
load-package.cmd -Package C:\packages\TASK-123.zip -File C:\Bases\Test -User Администратор -BackupCf C:\Backups
```

Только загрузить в основную конфигурацию, не обновляя конфигурацию базы данных (например, чтобы обновить
позже в окно обслуживания):

```
load-package.cmd -Package C:\packages\TASK-123.zip -Server srv1c -Ref test_base -User Администратор -NoUpdateDB
```

### Пароль

Пароль 1С передаётся одним из способов:

- параметром `-Password <пароль>` — просто, но пароль виден в командной строке и истории;
- переменной окружения `ONEC_PASSWORD` — удобно для автоматизации (секрет из хранилища CI):

  ```
  set ONEC_PASSWORD=<пароль>
  load-package.cmd -Package C:\packages\TASK-123.zip -Server srv1c -Ref test_base -User Администратор
  ```

Если у пользователя нет пароля, ничего не указывать.

### Встраивание в автоматизацию

Достаточно проверить код возврата:

```
call load-package.cmd -Repo %REPO% -Branch %TASK_BRANCH% -Server %SRV% -Ref %IB% -User %IB_USER% -Log C:\logs\load.log
if errorlevel 1 exit /b 1
```

## Параметры

| Параметр | Что это |
|---|---|
| `-Package <zip>` | zip-файл пакета |
| `-Repo <URL или путь>` | репозиторий с веткой пакетов (вместо `-Package`) |
| `-Branch <ветка>` | ветка задачи: из ветки пакетов берётся `<ветка>.zip` (`feature/TASK-123` → `feature/TASK-123.zip`) |
| `-PackagesBranch <ветка>` | ветка пакетов, по умолчанию `packages` |
| `-File <каталог>` | файловая база |
| `-Server <сервер>` `-Ref <имя>` | серверная база: сервер 1С (можно с портом, `srv1c:1541`) и имя базы на нём |
| `-User <имя>` | пользователь 1С |
| `-Password <пароль>` | пароль; по умолчанию — из переменной `ONEC_PASSWORD` |
| `-UC <код>` | код разрешения входа, если в базе установлена блокировка сеансов |
| `-Platform <путь>` | путь к `1cv8.exe`; по умолчанию — самая новая версия в `Program Files\1cv8` |
| `-BackupCf <файл или каталог>` | сохранить конфигурацию в `.cf` перед загрузкой; для каталога имя — `backup_<база>_<дата>.cf` |
| `-NoUpdateDB` | не обновлять конфигурацию базы данных |
| `-Log <файл>` | куда писать журнал конфигуратора (по умолчанию — во временный каталог) |
| `-KeepTemp` | не удалять временный каталог даже при успехе |

## Что важно знать

- **Монопольный доступ.** Обновление конфигурации базы данных требует, чтобы в базе не было других сеансов.
  Перед загрузкой сеансы нужно завершить или заблокировать (с блокировкой — передать `-UC`).
- **Пакет рассчитан на определённое состояние базы** — в `info.txt` это строка «Коммит базы». Если база
  отстаёт от этого коммита или ушла вперёд по тем же объектам, загрузка может откатить чужие изменения или не
  пройти. Надёжнее всего — база, собранная из этого коммита.
- **Конфигурация должна быть та же.** Частичная загрузка сверяет идентификатор конфигурации: в базу другой
  конфигурации (или в пустую) пакет не загрузится.
- **Удалённые объекты** частичная загрузка не удаляет — они перечислены в `info.txt`.
- **Данные** (константы, элементы справочников) пакет не переносит — только конфигурацию.
- **Поддержка поставщика.** Если объекты пакета стоят на замке поддержки, конфигуратор их не изменит.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| «Не найден 1cv8.exe» | указать `-Platform "C:\Program Files\1cv8\<версия>\bin\1cv8.exe"` |
| «В каталоге нет файловой базы (1Cv8.1CD)» | проверить `-File` |
| «не удалось получить ветку packages» | проверить URL, доступ к репозиторию без запроса пароля, `-PackagesBranch` |
| «в ветке packages нет пакета …» | пакет этой ветки ещё не отправлен или ветка указана неточно |
| «идентификатор … загружаемой конфигурации отличается…» | база другой конфигурации — пакет предназначен не для неё |
| ошибка блокировки или «монопольный режим» | завершить сеансы в базе или передать `-UC` |
| ошибка авторизации 1С | проверить `-User`, пароль, права пользователя |
| загрузка завершилась с кодом 1 | причина — в журнале конфигуратора выше; пакет лежит во временном каталоге, путь указан в конце |

Сохранённый через `-BackupCf` `.cf` можно вернуть в базу конфигуратором: «Конфигурация → Загрузить
конфигурацию из файла» и обновить конфигурацию базы данных.
